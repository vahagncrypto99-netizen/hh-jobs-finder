# hh-jobs — меню-бар приложение управления пайплайном

Tauri-приложение в стиле naeasy: живёт **только в меню-баре**, иконки в доке нет
(`ActivationPolicy::Accessory`). Окно — Spotlight-style NSPanel с нативной
прозрачностью: клик по иконке в трее открывает/прячет, Escape и потеря фокуса
закрывают, красный крестик прячет, а не завершает. Интерфейс на английском,
стили — `styles.css` из naeasy плюс блок дополнений в конце файла.

Две табы:

- **Run** — статусы (pipeline / scheduler / hh.ru session), кнопка `Check` для проверки
  входа, ручной запуск с чекбоксом `Dry run` и стопом, панель прогресса, расписание
  launchd чипами (добавить/править/удалить время).
- **Settings** — режим письма (`Written by: AI | Template`), поисковые запросы,
  фильтры hh.ru (`Posted within` — реальные значения `search_period`: 1/3/7/30/0,
  зарплата + валюта, опыт, формат работы, регион, сниппеты) и лимиты прогона.

**Кнопок «Сохранить» нет — всё пишется само.** Правка формы уходит в `config.yaml`
через 600 мс после последнего нажатия, изменение расписания — через 1 с (дольше,
потому что следом перезагружается агент launchd). Пока правка в очереди или курсор
стоит в поле, поллинг не перерисовывает форму, чтобы не увести каретку. Если запись
не прошла (например, стёрли все поисковые запросы), файл остаётся нетронутым, а
причина показывается в строке статуса внизу.

## Иконки

`app/scripts/make-icons.swift` рисует их напрямую через CoreGraphics:
`swift app/scripts/make-icons.swift app/src-tauri/icons`, затем
`iconutil -c icns app/src-tauri/icons/icon.iconset -o app/src-tauri/icons/icon.icns`.

Через SVG + `qlmanage` не получится: QuickLook рендерит превью **документа** и кладёт
его на непрозрачную белую страницу — template-иконка в меню-баре превращается в белый
квадрат. Поэтому генератор проверяет угловой пиксель каждого PNG и падает, если альфа
не нулевая.

Единственный источник правды — `../config.yaml`:

- правка в UI → точечная запись в файл **с сохранением комментариев** (строчный
  редактор в `src-tauri/src/lib.rs`, после записи файл валидируется как YAML);
- правка файла руками → UI перечитывает его по mtime (поллинг каждые 2 с). Если в
  форме есть несохранённые изменения, а файл поменялся на диске — показывается баннер
  конфликта с кнопкой «Перечитать»;
- кнопка `config.yaml ↗` в шапке открывает файл в редакторе по умолчанию (`open`).

При сохранении расписания `ProgramArguments` в plist переписывается на голый
`hhru-jobs` **без флагов** `--w`/`-c` — чтобы запуски по расписанию тоже брали
воркеров и лимит из `config.yaml`, а не из зашитых аргументов.

## Панель прогресса

Показывает, что пайплайн делает прямо сейчас: стадию (`Searching vacancies` →
`Analyzing vacancies` → `Writing cover letters` → `Submitting applications` →
`Finished`) и счётчики found / analyzed / skipped / applied / failed. Кнопка
`Details` раскрывает сырой лог.

Числа берутся **не из лога, а из `data/vacancies-registry.yaml`** — его пишет сам
пайплайн, поэтому счётчики не врут даже если формат вывода поменяется. Считаются
построчным сканом (файл ~300 КБ, парсить YAML на каждом опросе дорого). При старте
прогона снимается снимок реестра, поэтому в заголовке `Progress — this run`
показываются дельты именно этого запуска; без снимка (например, запуск по
расписанию, пока приложение было закрыто) — `Progress — registry total`.

Стадия определяется по маркерам `[subagent_type: hh-*]` в логе. Поэтому запуски по
расписанию тоже пишутся с `--verbose`: при сохранении расписания приложение
проставляет этот флаг в plist.

## Проверка авторизации — без ИИ

`app/scripts/check-auth.mjs` находит профиль Playwright MCP (самый свежий каталог
`mcp-*` под `~/Library/Caches/ms-playwright-mcp`, в котором есть cookies hh.ru),
открывает его headless-браузером через `playwright-core` и запрашивает
`https://hh.ru/applicant/resumes`. Занимает ~5 секунд, LLM не участвует.

Профиль открывается каналом `chrome` — тем же, которым его создал MCP: иначе macOS
Keychain не отдаст ключ и cookies не расшифруются (проверка ложно покажет «нет входа»).
Если браузер пайплайна уже открыт, профиль заблокирован — кнопка вернёт «профиль занят».

Из терминала: `./scripts/check-auth.sh` (0 — вход есть, 2 — нет, 1 — ошибка окружения).

## Установка

`./install.sh` в корне репозитория ставит всё разом: проверяет node/npm/claude/cargo,
регистрирует **playwright MCP** (`claude mcp add playwright --scope user`), докачивает
браузеры, ставит зависимости приложения и собирает `.app`.

```bash
./install.sh                  # полная установка
./install.sh --check          # только диагностика, ничего не меняет
./install.sh --with-schedule  # плюс launchd-агент
```

## Запуск

```bash
cd app
npm install        # один раз
npm run dev        # окно разработки
npm run build      # сборка .app
```

Ручной запуск пайплайна пишет лог в `data/run-reports/app-manual.log`
(кнопка «Лог ↗» открывает его). Корень репозитория ищется относительно
`CARGO_MANIFEST_DIR`, переопределяется переменной `HHRU_ROOT`.
