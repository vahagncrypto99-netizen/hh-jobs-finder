# hh-jobs-finder

Приложение в меню-баре macOS, которое само откликается на вакансии hh.ru: ищет по твоим
фильтрам, отсеивает неподходящие, пишет персональное сопроводительное письмо под каждую
и отправляет отклик. По расписанию или по кнопке.

Внутри — пайплайн на [Claude Code](https://claude.com/claude-code) и Playwright, но лезть
туда не нужно: всё управление в приложении и одном файле `config.yaml`.

---

## Установка

Нужны: macOS, [Claude Code](https://claude.com/claude-code), Node.js 18+, Google Chrome,
Rust (`cargo`) для сборки приложения. И аккаунт hh.ru с опубликованным резюме.

```bash
git clone git@github.com:vahagncrypto99-netizen/hh-jobs-finder.git
cd hh-jobs-finder
./install.sh
```

`install.sh` проверит зависимости, подключит Playwright MCP, докачает браузеры, соберёт
приложение и скажет, чего не хватает. Готовый бандл:

```
app/src-tauri/target/release/bundle/macos/hh-jobs.app
```

Перетащи его в `/Applications` и запусти. Иконка появится в меню-баре — в доке её нет.

---

## Первый запуск

1. **Settings → Set resume…** — выбери своё резюме (pdf, docx, md, txt). Приложение разберёт
   его и заполнит `config.yaml` и `resume.md`. Бейдж рядом станет `ready`.
2. **Вход в hh.ru** — один раз, в терминале: `claude`, затем `/hh:login`. Откроется браузер,
   залогинься руками и напиши «готово». Cookies осядут в профиле, дальше вход не потребуется.
3. **Run → Check** — убедись, что сессия жива (`signed in`).
4. **Run → Dry run + Run now** — прогон без реальных откликов. Посмотри в реестре, какие
   вердикты вышли и что за письма получились.
5. Всё устраивает — сними `Dry run` и жми `Run now`. Или задай расписание.

## Приложение

Клик по иконке в меню-баре открывает панель, повторный клик или Escape — прячет. Панель
закрывается сама, когда фокус уходит. В меню иконки (правый клик) — `Открыть` и `Выйти`.

### Таб Run

**Status** — три строки состояния:

| Строка | Что показывает |
|---|---|
| `Pipeline` | `idle` · `running (manual)` · `running (scheduled)` · `finished` · `failed (код)` |
| `Scheduler` | загружен ли launchd-агент |
| `hh.ru session` | результат последней проверки входа; кнопка `Check` перепроверяет за ~5 секунд |

`Check` не тратит ИИ: открывает профиль браузера напрямую и запрашивает страницу резюме.
Пока идёт прогон, кнопка заблокирована — профиль браузера занят пайплайном.

**Manual run** — `Run now` запускает пайплайн, чекбокс `Dry run` проходит весь цикл, но не
отправляет отклики. Пока прогон идёт, вторая кнопка — `Stop`; когда всё тихо — `Log`,
открывающая полный лог файлом.

`Stop` останавливает любой активный прогон, а не только запущенный из приложения: если
пайплайн стартовал по расписанию или приложение перезапускали посреди работы, он всё равно
будет остановлен — вместе с дочерним процессом, иначе тот продолжил бы рассылать отклики.

**Progress** — что происходит прямо сейчас:

```
Progress — this run
Searching vacancies                     [Details]
   5         3         2         1
 found   analyzed   skipped   applied
```

Стадии сменяются так: `Searching vacancies` → `Analyzing vacancies` → `Writing cover letters`
→ `Submitting applications` → `Finished`. Счётчики считаются по реестру вакансий, а не по
логу, поэтому они точные. `Details` раскрывает живой лог. Заголовок `this run` означает, что
показаны цифры текущего запуска; `registry total` — что приложение открыли уже во время
прогона по расписанию и точку отсчёта взять неоткуда.

**Уведомления** — когда прогон заканчивается, приходит системное уведомление с итогом
(`Run finished — found 5, applied 2, skipped 3`) или с кодом ошибки. Работает и для ручных
запусков, и для запусков по расписанию, если приложение открыто. Тот же итог дублируется
строкой внизу панели: macOS иногда не пускает уведомления от приложений без подписи
разработчика — перенеси `.app` в `/Applications` и разреши уведомления в
«Системные настройки → Уведомления», если системных всплывашек нет.

**Schedule** — время запусков чипами. `＋ Time` добавляет, `✕` удаляет, время правится прямо
в чипе. Сохраняется само, агент launchd перезагружается сам. Запуски по расписанию берут
количество воркеров и лимит вакансий из `config.yaml`.

### Таб Settings

Кнопок «Сохранить» нет: правки уходят в `config.yaml` через полсекунды после последнего
нажатия. Комментарии и форматирование файла при этом сохраняются. Правишь файл в редакторе —
панель подхватывает изменения сама.

| Настройка | Что делает |
|---|---|
| **Set resume…** | импорт резюме: заполняет `config.yaml` и `resume.md` |
| **Written by** | `AI` — письмо пишется под каждую вакансию; `Template` — сборка по шаблону без ИИ |
| **Search queries** | поисковые запросы; обходятся по очереди, пока не набран лимит вакансий |
| **Posted within** | за какой срок искать: сутки, 3 дня, неделя, месяц, всё время |
| **Minimum salary** | нижняя граница и валюта |
| **Experience** | требуемый опыт по классификации hh.ru |
| **Work format** | удалёнка, гибрид, офис, разъездная |
| **Search all regions** | искать без привязки к региону |
| **Parallel workers** | сколько вакансий анализируется одновременно |
| **Vacancies per run** | максимум новых вакансий за один запуск |

Кнопка `✎` в шапке открывает `config.yaml` в редакторе, `⏻` — выход из приложения.

## Ручное редактирование config.yaml

Приложение и файл — одно и то же: что удобнее, тем и правь. В панели вынесено самое частое,
остальное (правила матчинга, валидация писем) — только в файле.

Файл приватный, в git не попадает. Если его нет — `cp config.yaml.example config.yaml`.

### Поиск

```yaml
search:
  base_url: "https://hh.ru/search/vacancy"
  filters:
    text: ["Laravel", "Backend разработчик"]  # запросы обходятся по очереди
    salary: 2000                              # минимальная зарплата
    currency_code: "USD"       # USD | EUR | RUR | KZT | UAH | GEL | AZN | KGS | UZS | BYR
    experience: "between3And6" # noExperience | between1And3 | between3And6 | moreThan6
    work_format: "REMOTE"      # REMOTE | HYBRID | ON_SITE | FIELD_WORK
    no_default_area: true      # искать по всем регионам
    enable_snippets: false
    search_period: 3           # за сколько суток: 1 | 3 | 7 | 30 | 0 (за всё время)
```

### Личное и лимиты

```yaml
resume_title: "Backend-разработчик (PHP/Laravel)"  # должно совпадать с резюме на hh.ru

defaults:
  workers: 1    # параллельных анализов
  count: 20     # максимум новых вакансий за запуск

pause_between_applies_sec: [5, 15]  # случайная пауза между откликами

contacts:                 # подставляются в письмо байт в байт
  portfolio: "https://github.com/username"
  telegram: "@username"
  phone: "+00-00-00-00-00"

signature: "Имя Фамилия"
```

### Правила отсева

Этот блок решает, какие вакансии отбрасываются. Причина скипа пишется в реестр,
в поле `verdict_reason` — если отсев кажется странным, смотри туда.

```yaml
matching:
  title_blacklist: [Team Lead, Тимлид, CTO]     # слово в заголовке → скип
  title_ok_levels: [Senior, Middle, Middle+]    # уровни, которые скипом НЕ считаются
  framework_blacklist: [Yii2, Symfony, Bitrix]  # чужой основной фреймворк → скип
  primary_languages: [PHP]                      # основной язык вакансии
  core_stack: [PHP, Laravel, PostgreSQL, Redis] # совпадение → match
  frontend_stack: [JavaScript, Vue, Nuxt]       # подходящий фронт для fullstack-вакансий
  acceptable_secondary: [React, TypeScript]     # не профиль, но и не блокер
  learnable_tech: [Livewire, Alpine.js]         # отсутствие в резюме не считается пробелом
  ignore_resume_skills: []                      # что из резюме не учитывать при матчинге
  recheck:
    max_experience_years: 6      # «опыт от 7 лет» в описании → скип
    reject_if_office_only: true  # «только офис» → скип
  doubt_policy: match            # что делать при сомнении: match | skip
```

### Письма

```yaml
letter:
  mode: ai                          # ai | template
  template: "templates/letter.md"

letter_validation:
  length_range: [500, 900]          # знаков, без контактов и подписи
  max_iterations: 5                 # сколько раз переписывать, пока не сойдётся
  ru_ai_check_min_score: 7.0        # проходной балл естественности текста (0–10)
  required_tech_mentions: [1, 2]    # сколько общих технологий назвать явно
```

**Режим `ai`** пишет письмо под конкретную вакансию: выбирает одно релевантное достижение
из `resume.md` и прогоняет текст через проверки на естественность, длину и фактическую
точность. **Режим `template`** подставляет переменные в `templates/letter.md` — мгновенно и
бесплатно, но письма внутри одной темы получаются почти одинаковыми. Свой шаблон:
`cp templates/letter.md.example templates/letter.md`.

### resume.md

Второй приватный файл и единственный источник фактов для писем. Заполняется кнопкой
`Set resume…`, но раздел **«Достижения с метриками»** стоит проверить руками: цифры оттуда
попадают в письма дословно, выдумывать их запрещено. Раздел **«Чего НЕТ»** страхует от
приписывания несуществующего опыта.

## Диагностика

| Симптом | Что делать |
|---|---|
| `hh.ru session: signed out` | сессия истекла: `claude` → `/hh:login` |
| `Check` пишет «профиль занят» | идёт прогон, браузер занят — дождись конца |
| `Scheduler: not loaded` | добавь время в `Schedule` или запусти `./install.sh --with-schedule` |
| Прогон нашёл 0 вакансий | ослабь фильтры: `Posted within`, `Minimum salary`, `Experience` |
| Все вакансии в `skipped` | слишком строгие `title_blacklist` / `framework_blacklist`; причина каждого скипа — в реестре, поле `verdict_reason` |
| Письма не сходятся за 5 итераций | мало конкретики в «Достижениях с метриками» — добавь цифр |
| `failed` сразу после запуска | открой `Log`: чаще всего не найден `claude` — проверь `./install.sh --check` |

## Что входит в комплект

Всё, что нужно пайплайну, лежит в репозитории — доустанавливать скиллы вручную не нужно.
`./install.sh --check` проверяет комплектность.

| Компонент | Что делает |
|---|---|
| `hh-collector` | агент: обходит поисковую выдачу, собирает новые вакансии |
| `hh-analyzer` | агент: сверяет вакансию с резюме, выносит `match` / `skip` |
| `hh-letter` | агент: пишет сопроводительное письмо |
| `hh-applier` | агент: отправляет отклик (модалка, чат или тест работодателя) |
| `/hh:init` | команда: заполняет `config.yaml` и `resume.md` по резюме |
| `/hh:login` | команда: разовый вход в hh.ru |
| `/hh:run` | команда: дирижёр всего прогона |
| `hh-parsing` | скилл: селекторы выдачи, пагинация, схема данных |
| `hh-matching` | скилл: правила отсева и матчинга |
| `hh-letter` | скилл: структура письма, метод X-Y-Z, три гейта |
| `hh-applying` | скилл: три сценария отклика, проверка результата |
| `ru-ai-check` | скилл: оценка письма 0–10 (Gate 1) |

`ru-ai-check` — это [ru-text](https://github.com/talkstream/ru-text) Арсения Камышева под
лицензией MIT, включённый в репозиторий как есть (см. `.claude/skills/ru-ai-check/LICENSE`
и `PROVENANCE.md` — там же команда обновления до свежей версии апстрима). Без него не
отработает проверка письма на естественность.

Единственная внешняя зависимость, которая ставится отдельно, — **Playwright MCP**; это
делает `install.sh`.

## Приватность

`config.yaml`, `resume.md`, шаблон письма и весь каталог `data/` (реестр вакансий, письма,
отчёты, логи) в git не попадают — правила в `.gitignore`. Система ничего никуда не отправляет,
кроме самих откликов на hh.ru от твоего имени.
